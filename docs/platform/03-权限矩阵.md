# 03 · 权限矩阵（RBAC + 数据范围 V1）

> 原则（PRD §5）：默认拒绝；前端隐藏仅为体验，**服务端逐请求校验**；组织数据隔离；切换身份/组织刷新权限上下文并清空端侧缓存；高风险动作分权 + 审计。

## 1. 校验管线（服务端中间件顺序）

```
请求 → 鉴权(token有效/未撤销) → 上下文(identity_id, org_id)
    → 身份/成员关系解析(查库得角色集)
    → role_permissions 匹配 resource:action（无匹配=403）
    → data_scope 过滤查询条件(self / own_org / granted_scope / platform / all)
    → 资源级复核(所属关系、状态机前置、版本) → 执行 → 审计
```

- `perm_version`：角色/成员关系变更时递增（存 organizations/accounts 元数据）；令牌内版本过期即强制重新拉取上下文。
- 缓存键必须含 `account_id + org_id + perm_version`；登出/切换即清（客户端契约）。

## 2. 角色集

| 角色 | 来源 |
|---|---|
| user / student / athlete / coach / mentor | identities.identity_type |
| org_admin / org_member | memberships.role（组织上下文内） |
| event_organizer / content_editor / reviewer / platform_ops / platform_admin | identities.identity_type（平台授予，需显式平台授权记录） |

同一请求生效角色 = 当前 identity_type + 当前 org 上下文的 membership.role（org 资源类）+ 资源归属关系（本人/本人课程/本人赛事）。

## 4. 跨组织隔离规则

1. 组织 A 的任何角色都不能读取组织 B 的成员/课程/报名/名单/导出（URL、API 参数、导出三通道同规则，由 data_scope 过滤保证）。
2. 平台角色跨机构操作需显式平台授权记录（identities + 审计），非默认能力。
3. 无权访问返回 `403`，不暴露资源存在性。
4. 权限/隐私撤销即时生效：membership 状态变更/授权 revoke → perm_version 递增 + Outbox 通知两端清缓存；服务端不再放行后续请求。

## 5. 权限测试用例（阶段2/4 验收随附）

跨组织读取拒绝 / 无权动作拒绝 / 角色变更立即生效 / 过期授权后读取失败 / 导出留审计 / 重复幂等提交仅一条 / 并发编辑 409 / 登出后令牌失效。
